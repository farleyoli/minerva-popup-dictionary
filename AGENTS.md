# AGENTS.md

Chrome extension (Manifest V2) that shows a Wiktionary definition popup on double-click. No build system, no package.json, no tests, no linter, no CI. Plain vanilla JS loaded directly by Chrome as an "unpacked" extension.

## Workflow

- There is no build/test/lint step. Do not run `npm`/`yarn`/`pip` or any test command.
- To verify changes: load the repo as an unpacked extension (`chrome://extensions` → "Load unpacked"), then double-click a word on a page and reload the extension after edits.
- No `.gitignore` or CI config exists.

## Architecture

- `manifest.json` is the source of truth for what loads and in what order. It wires three contexts:
  - `fg/` — content scripts (run inside the page): `utils.js`, `content.js`, `anki.js`, `listeners.js` + `popup.css`.
  - `bg/` — background page (`bg/background.html`): `bg/anki.js`, `bg/listeners.js` (plus `bg/background.js`, which is empty).
  - `options_page` → `bg/options.html`.
- All scripts share one global scope (no modules/bundler). Functions and variables are global and cross-file. Load order from `manifest.json` matters; renaming a function (e.g. `addCard`, `processDefinition`) requires checking all files. Note `fg/content.js` uses many implicit globals (`ret`, `count`, etc.).
- `dictionary/` — data, not code: `a.json`…`z.json` (word → definition), `ipa.json` (IPA), `freq.json` (frequency), `trie.json` (used for fuzzy "suggestions"). These are large (up to ~33 MB for `trie.json`).

## Gotchas

- Dictionary lookup in `fg/content.js` fetches `./dictionary/<firstLetter>.json`. `getFirstLetter()` (in `fg/utils.js`) lowercases the first letter, or returns `"other"` for non-letter starts — but there is no `other.json`, so non-alphabetic words fail.
- Lookup fallback chain in `processDefinition()`: exact word → `trim()` → `toLowerCase()`.
- Anki integration requires Anki + the Anki-connect addon listening on `http://127.0.0.1:8765`. Deck name `"Default"` and the cloze note model `"minerva-popup-dictionary"` are configured in `bg/anki.js`; `ensureMinervaModel()` recreates the model (deleting its notes via `removeEmptyNotes`) if the existing model's fields/template don't match. The example phrase is stored as `{{c1::word}}` cloze markup, produced by `getExamplePhrase()` in `fg/utils.js`.
- `dictionary/trie.json` is generated by `dictionary/construct-trie.py`, which must be run **from inside `dictionary/`** (it relies on `os.getcwd()`). It regenerates the trie from the letter JSON files.
- `fg/popup.js`, `bg/options.js`, and `fg/anki.js`'s `getDeckNames` are leftover from the Chrome getting-started sample (color-button demo) and are effectively dead/unused.
