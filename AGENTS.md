# AGENTS.md

Chrome extension (Manifest V2) that shows a Wiktionary definition popup on double-click. No build system, no package.json, no linter, no CI. Plain vanilla JS loaded directly by Chrome as an "unpacked" extension.

## Workflow

- No build/lint step. Do not run `npm`/`yarn`/`pip`.
- Tests: `node --test test/` runs the Node regression tests (the extension scripts are loaded via `vm` and don't need a browser).
- To verify changes: load the repo as an unpacked extension (`chrome://extensions` → "Load unpacked"), then double-click a word on a page and reload the extension after edits.
- No `.gitignore` or CI config exists.

## Architecture

- `manifest.json` is the source of truth for what loads and in what order. It wires three contexts:
  - `fg/` — content scripts (run inside the page): `utils.js`, `content.js`, `anki.js`, `listeners.js` + `popup.css`.
  - `bg/` — background page (`bg/background.html`): `bg/anki.js`, `bg/deepseek.js`, `bg/listeners.js` (plus `bg/background.js`, which is empty).
  - `options_page` → `bg/options.html`.
- All scripts share one global scope (no modules/bundler). Functions and variables are global and cross-file. Load order from `manifest.json` matters; renaming a function (e.g. `addCard`, `processDefinition`) requires checking all files. Note `fg/content.js` uses many implicit globals (`ret`, `word`, `pos`, etc.).
- `dictionary/` — data, not code: `a.json`…`z.json` (word → definition), `ipa.json` (IPA), `freq.json` (frequency), `trie.json` (used for fuzzy "suggestions"). These are large (up to ~33 MB for `trie.json`).

## Gotchas

- Dictionary lookup in `fg/content.js` fetches `./dictionary/<firstLetter>.json`. `getFirstLetter()` (in `fg/utils.js`) lowercases the first letter, or returns `"other"` for non-letter starts — but there is no `other.json`, so non-alphabetic words fail.
- Lookup fallback chain in `processDefinition()`: exact word → `trim()` → `toLowerCase()`.
- Anki integration requires Anki + the Anki-connect addon listening on `http://127.0.0.1:8765`. The deck name is user-configurable via the options page (`bg/options.html`, default `"Minerva Extension"`, stored in `chrome.storage.sync` under `deckName`). `bg/anki.js` manages two cloze note models through model descriptors (`MINERVA_MODEL`, `AI_MODEL`): `"minerva-popup-dictionary"` and `"minerva-popup-dictionary-ai"`. The lifecycle helpers (`ensureModel`, `migrateModel`, `removeModel`, `updateModelStyling`, `wordExistsInDeck`, `addNoteToModel`) are generic over the descriptor, so renaming a model or adding a field means editing its descriptor plus `test/anki-connect.test.js`. The example phrase is stored as `{{c1::word}}` cloze markup with each sentence on its own `<p>` paragraph, produced by `getExamplePhrase()` → `wrapExamplePhraseInParagraphs()` in `fg/utils.js`. `getExamplePhraseText()` returns the same context as raw text (used for the DeepSeek prompt and the AI card's answer-side `original-phrase` field).
- The options page's "Card type" setting (`cardType`, `chrome.storage.sync`) chooses between `"page"` (existing behavior) and `"deepseek"` (AI-generated phrase). The AI card is added to `"minerva-popup-dictionary-ai"`, which adds an `original-phrase` field rendered at the bottom of the card Back. `fg/content.js`'s `addCardFromPopup()` requests the phrase from the background (`generateExamplePhrase` message), wraps it with the cloze helper, and falls back to the page phrase if the request fails or produces no cloze marker.
- DeepSeek integration lives in `bg/deepseek.js` and only runs in the background page. The API key is pasted in the options page and stored in `chrome.storage.local` under `deepseekApiKey` (never sent to content scripts). `generateExamplePhrase()` calls `https://api.deepseek.com/chat/completions` with model `deepseek-chat`, a 30s abort timeout, and a GRE-textbook-style 2–3 sentence passage prompt built from the word, the plain-text definition, and the raw page context. Daily usage is tracked in `chrome.storage.local` under `deepseekUsage` (`{date, tokens}`, reset on date change) and compared against `deepseekDailyTokenLimit` in `chrome.storage.sync` (default `30000`, roughly 50 phrases; `0` disables the limit). Once spent, `generateExamplePhrase()` throws an error with `reason: "limit"`, which `bg/listeners.js` forwards so the content script can show "Daily AI limit reached — adding page phrase" before adding the normal card.
- `dictionary/trie.json` is generated by `dictionary/construct-trie.py`, which must be run **from inside `dictionary/`** (it relies on `os.getcwd()`). It regenerates the trie from the letter JSON files.
- `fg/popup.js` and `fg/anki.js`'s `getDeckNames` are leftover from the Chrome getting-started sample (color-button demo) and are effectively dead/unused.
